These changes must be applied by Antigravity in the local production repository for `cvss.helpusbr.com`. The review archive does not contain the complete web application source, so they cannot be safely patched here.

## Release-blocking scientific synchronization

1. Remove or qualify all current claims that imply the 30-case Dataset B is confirmatory scientific validation. Use `Development Benchmark` / `development-stage observation`.
2. Do not present `25%` as an accuracy/noise-reduction KPI. If shown at all, label it explicitly as `3/12 legacy development-stage High/Critical-to-below-High transition observation`, not a false-positive rate.
3. Remove `100% agreement`, `100% correctness`, `zero hallucination`, `guaranteed`, `immutable`, or equivalent absolute claims unless a specific measured construct and denominator are shown.
4. Ensure the public engine uses the same fail-safe behavior as `core/ai_evidence_engine.py`: missing, stale, conflicting or unknown reachability evidence -> `HUMAN_REVIEW_REQUIRED`; no automatic downgrade.
5. `internal-only` must **not** imply `MAV:A`. Internal L3-routed reachability remains `MAV:N`; `MAV:A` requires demonstrated adjacent-domain semantics; `MAV:L` requires local execution semantics.
6. Firewall/WAF presence must not automatically set `MAC:H`.
7. CR/IR/AR must come from an explicit versioned organizational policy mapping, not directly from PCI/regulated-data flags.
8. High availability/redundancy must not map to `AR:L`; approved availability mitigations belong, when semantically valid, in modified impact (e.g. MVA), while AR expresses organizational availability requirement.
9. Display source assessment provenance: provider, source system, vector, score, nomenclature (`CVSS-B`, `BT`, `BE`, `BTE`), and retrieval timestamp.
10. Display HelpUS-derived CVSS Environmental result separately from local operational disposition P0-P4.
11. `P4_DEFER_RECOMMENDED` must not be displayed as accepted risk; acceptance requires authorized human approval.
12. Preserve a machine-readable audit receipt: JSON Schema validation -> RFC 8785 canonicalization -> SHA-256; signatures/Merkle/timestamps are separate mechanisms.
13. Any historical Cisco/Trento preset must be labeled historical/illustrative and must not hard-code the old additive score deltas or claim a validated v4.0 result unless generated by the current engine from documented evidence.
