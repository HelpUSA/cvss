# CG-20261013-028
## Formal Scientific Scope Pivot — Non-Human Primary Study / Autonomous Environmental CVSS Validation

## 1. Executive Decision

The project’s **primary scientific study is redefined as a non-human technical validation study**.

The original 5-expert human adjudication study is removed from the critical path and reclassified as an **optional future extension**.

This pivot is motivated by the actual product proposition:

> HelpUS CVSS should detect and structure the environment, resolve environmental/modified metrics from verifiable context, and calculate CVSS v4.0 deterministically without requiring routine human expert participation.

The product itself must not depend on ChatGPT, Gemini, or Antigravity. Those systems are development/audit collaborators only.

## 2. Primary Scientific Question

Replace the human-agreement-centered question:

> “Does the system agree with five independent experts?”

with the primary engineering/scientific question:

> “Given a verifiable set of environmental characteristics, can HelpUS CVSS derive CVSS v4.0 environmental and modified metrics correctly, reproducibly, and audibly according to FIRST semantics and deterministic policy rules?”

## 3. Scope of the Primary Study

Primary validation should rely on:

- FIRST specification semantics;
- deterministic scoring engine;
- canonical corpus/vector conformance;
- synthetic environmental profiles;
- deterministic environmental rule catalog;
- metamorphic/property-based testing;
- adversarial/context-conflict testing;
- reproducible clean-room execution;
- public vulnerability/advisory data where legally appropriate;
- non-personal technical infrastructure metadata;
- explicit provenance of every environmental metric decision.

No human participant is required for the primary study.

## 4. Human Study Status

The 5-expert protocol is no longer required to complete or publish the primary technical study.

New status:

**HUMAN_EXPERT_STUDY = OPTIONAL_FUTURE_EXTENSION**

It may later be conducted as a separate study/paper if useful for:

- human agreement;
- usability;
- trust calibration;
- analyst acceptance;
- external expert validation.

Historical G9/G10 documents must be preserved for auditability and must not be deleted.

## 5. Ethics / Regulatory Consequence

If the primary study:

- recruits no participants;
- obtains no human judgments;
- performs no interaction/intervention with living individuals;
- uses no identifiable private information about individuals as research data;

then the project should not be represented as a human-subjects study merely because the software is developed or operated by people.

However:

- do not claim blanket “legal exemption”;
- do not state “no law applies”;
- privacy, contracts, cybersecurity, confidentiality, sectoral requirements, and data-protection obligations may still apply;
- any future human study reactivates the relevant ethics/jurisdiction workflow;
- if real infrastructure data contains personal data, privacy/legal analysis remains required.

## 6. Product Architecture

The product architecture should be technology-independent:

`Evidence Ingestion -> Context Engine -> Deterministic Policy/Rule Engine -> Metric Resolver -> Canonical FIRST CVSS v4.0 Engine -> Prioritization/Output`

ChatGPT, Gemini, and Antigravity are **not production dependencies**.

They may continue to support development/audit, but the product specification must remain implementation-neutral.

## 7. Environmental Context Model

HelpUS should ingest structured sources such as:

- CMDB;
- cloud inventory/tags;
- network topology;
- exposure paths;
- firewall/segmentation;
- IAM/MFA;
- WAF;
- EDR;
- SIEM evidence;
- Kubernetes / container context;
- application criticality;
- data classification;
- redundancy / HA;
- backup / RTO/RPO;
- service dependencies.

The platform should build a versioned `Asset Context Profile`.

## 8. Critical Rule: Control Presence Is Not Metric Change

Formal invariant:

**CONTROL_PRESENT != CONTROL_EFFECTIVE != CVSS_MODIFIED_METRIC**

A WAF, MFA, segmentation rule, backup, or EDR agent must not automatically change an M* metric.

A modified metric can be asserted only when a deterministic rule demonstrates that the actual environment changes the CVSS-defined condition relevant to that metric.

## 9. Environmental Rule Catalog

Create a versioned and testable rule catalog.

Conceptual example:

```text
RULE MAV-003
IF base_AV == N
AND internet_route == false
AND reachable_only_from_adjacent_network == true
AND network_path_evidence == VERIFIED
THEN MAV = A
```

Each decision should capture:

- metric;
- resolved value;
- source(s);
- evidence reference;
- rule identifier/version;
- evidence strength;
- timestamp/build;
- whether deterministic or inferred;
- abstention/escalation state if unresolved.

## 10. CR / IR / AR

CR/IR/AR can be derived from formal organizational classifications when those classifications are themselves controlled and versioned.

Examples of inputs:

- data sensitivity;
- legal/contractual criticality;
- operational criticality;
- service dependency;
- availability/redundancy;
- integrity consequences.

Do not infer business requirements from vague text when structured business classification is unavailable.

Use X / Not Defined or an explicit unresolved state when evidence is insufficient.

## 11. Straight-Through Processing

Recommended operational model:

**AUTOMATION_MODE = STRAIGHT_THROUGH_BY_DEFAULT**

**HUMAN_REVIEW = OPTIONAL_EXCEPTION_PATH, NOT ROUTINE REQUIREMENT**

**FORCED_GUESSING = PROHIBITED**

**INSUFFICIENT_EVIDENCE = ABSTAIN / UNRESOLVED / REQUEST_CONTEXT**

**FINAL_SCORE_ENGINE = DETERMINISTIC_ONLY**

The primary scientific study should validate the autonomous path without requiring humans in routine operation.

## 12. Validation Strategy Without Experts

### A. Mathematical conformance
- preserve existing FIRST corpus evidence;
- zero-divergence/regression;
- parser/fail-closed behavior.

### B. Environmental rule validation
Build deterministic scenarios where expected metric outcomes follow directly from FIRST semantics and explicit environmental facts.

### C. Property-based / metamorphic tests
Examples:

- increasing confidentiality criticality must not lower CR;
- removing verified isolation must not yield a less exposed MAV;
- adding an irrelevant control must not alter an unrelated metric;
- removing an effective relevant defense must not improve the environmental result;
- equivalent context encoded in different source order must yield identical output;
- missing required evidence must yield unresolved/abstain, not a guessed metric.

### D. Adversarial tests
- stale CMDB;
- contradictory controls;
- partial topology;
- false control claims;
- scanner/advisory mismatch;
- malformed inputs;
- poisoned metadata;
- conflicting asset tags.

### E. Reproducibility
- fixed rule versions;
- deterministic fixtures;
- build hashes;
- artifact manifests;
- clean-room replay.

## 13. Publication Strategy

Primary paper direction:

**Automated Context-Aware CVSS v4.0 Environmental Scoring**

Appropriate claims:

- normative conformance;
- deterministic contextualization;
- reproducibility;
- rule-based environmental resolution;

- robustness under synthetic/adversarial environmental scenarios.

- expert agreement;
- human ground truth validation;
- clinical/human-subject validation;
- FIRST endorsement/certification.

Optional second paper later:

**Human Expert Validation of Automated Environmental CVSS Assessments**

only if independently useful.
