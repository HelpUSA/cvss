### Finding C (G11-OPTIONAL-AI): Hard Non-Blocking Timeout Isolation for Hung Providers
**Problem Identified in CG-033:**
`with ThreadPoolExecutor(...) as executor:` in `gateway.py` called `executor.shutdown(wait=True)` upon exit, blocking the caller if a provider thread hung beyond the timeout.

**Implemented Solution:**
1. Replaced the `with ThreadPoolExecutor` construct in `core/ai_assurance/gateway.py` with explicit lifecycle management:
   - `done, not_done = concurrent.futures.wait(future_to_provider.keys(), timeout=timeout, return_when=ALL_COMPLETED)`
   - Canceled all futures in `not_done` and recorded `TIMEOUT` response with circuit-breaker metadata;
   - Enforced hard non-blocking shutdown in `finally`: `executor.shutdown(wait=False, cancel_futures=True)`.
2. Added `simulate_sleep_seconds` to `MockAIProviderAdapter` in `core/ai_assurance/provider_adapter.py`.
3. Added `test_11_hard_timeout_hanging_provider_does_not_block_gateway` in `tests/test_hcal_cognitive_assurance.py`:
   - Configures a provider that sleeps for 1.5 seconds with gateway timeout of 0.10 seconds;
   - Asserts execution returns in `< 0.45s` (measured `0.20s` in suite);
   - Asserts `ai_enrichment_status == "NOT_AVAILABLE"` and deterministic core scoring remains unaffected.
4. **Scope Clarification**: HCAL is declared strictly **OUTSIDE** the frozen release scope of the deterministic core. It is an experimental optional assurance layer that gracefully degrades to Mode 0 (CORE_AUTONOMOUS) under any condition.
