# CG-20261013-027

**INDEPENDENT_TECHNICAL_CORROBORATION**

not as:

**SOLE_CANONICAL_PROOF / FORMAL_CERTIFICATION / OFFICIAL_FIRST_HOMOLOGATION**

The canonical engineering evidence remains the project’s independently reproducible test corpus, CI, manifests, clean-room execution, and previously audited FIRST conformance evidence.

## 3. Important Qualifications to Gemini’s Report

### 3.1 “100% conformidade” must be bounded to evidence actually tested

The Gemini report references TC-01 through TC-10 and describes full conformity. Ten regression cases are useful sanity tests, but by themselves are insufficient to establish full CVSS v4.0 conformance.

The project already has much stronger canonical evidence: the large FIRST-derived corpus and prior zero-divergence validation.

Preferred wording:

> Gemini independently reproduced the expected outcomes for the reviewed regression set and found the architecture consistent with CVSS v4.0 principles; this corroborates, but does not replace, the canonical corpus-based conformance evidence.

Do not write that Gemini alone certified or officially homologated the engine.

### 3.2 FIRST endorsement/certification must not be implied

Gemini is not FIRST. Use “technical review against FIRST CVSS v4.0 materials” or “independent AI technical corroboration”. Do not use FIRST-certified, FIRST-approved, or officially homologated by FIRST.

### 3.3 Race conditions and AT:P must not be stated as an unconditional rule

FIRST v4.0 distinguishes AC (exploit engineering difficulty / bypass of security-enhancing techniques) from AT (prerequisite deployment/execution conditions). Race conditions are a classic example of AT:P, but metric assignment must follow the actual vulnerability conditions rather than a keyword rule.

Do not implement a universal if-race-condition-then-AT:P heuristic. Use rubric-based reasoning.

### 3.4 Supplemental metrics are optional enrichment only

The following supplemental metrics can be supported: Safety (S), Automatable (AU), Recovery (R), Value Density (V), Vulnerability Response Effort (RE), and Provider Urgency (U). They do not change the CVSS numerical score and must remain separated from scoring math.

Decision: **SUPPLEMENTAL_METRICS = ROADMAP / OPTIONAL_CONTEXT**.

### 3.5 v3.1 → v4.0 divergence module is explanation-only

The proposed divergence module is endorsed as explanatory migration support and analyst education. It must not adjust CVSS v4.0 scores, create hidden compensating weights, retune model predictions, or influence C1/C2 outcomes.

Decision: **V31_V40_DIVERGENCE = EXPLANATION_ONLY**.

### 3.6 Gemini’s regex is not sufficient as a strict edge validator

The shown regex ends with an open-ended .* suffix, so arbitrary trailing content may be accepted. It also must not replace the canonical parser.

Retain parser-based validation as authoritative. Regex may be a preliminary format filter only. Add negative tests for duplicate metrics, illegal order, invalid supplemental values, repeated segments, malformed suffixes, and partial vectors.

### 3.7 “zero-data retention” must not be inferred from AI Bridge Local alone

A local bridge can reduce exposure, but it does not by itself prove zero-data retention by downstream model providers.

Do not claim ZERO_DATA_RETENTION = VERIFIED unless separately evidenced by provider/account configuration, applicable product terms, transport/logging configuration, and retention controls.

Safer wording: “AI Bridge Local minimizes direct dissemination of project artifacts and provides local orchestration; provider-side data handling remains subject to the configured service/account terms and must be verified separately.”
