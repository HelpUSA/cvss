## 2. Diagnóstico e Remediação Técnica do CI (Workflow 38613007483)

### Causa Raiz
No arquivo `web/src/lib/operational-tenant-scope.ts`, a função `operationalAssessmentScopeWhere` retornava um objeto literal contendo:
```typescript
status: {
  in: ["DRAFT", "ACTIVE"]
}
```
No TypeScript, o array de strings literais era inferido como `string[]`, gerando incompatibilidade com o tipo gerado pelo Prisma `OperationalAssessmentStatus[] | EnumOperationalAssessmentStatusFilter` (erro `TS2322` na rota `POST .../runs/route.ts`).

### Remediação Aplicada
1. Importou-se `OperationalAssessmentStatus` e `type Prisma` de `@prisma/client`.
2. A cláusula foi tipada com `OperationalAssessmentStatus.DRAFT` e `OperationalAssessmentStatus.ACTIVE`.
3. Utilizou-se o operador `satisfies Prisma.OperationalAssessmentWhereInput` no objeto retornado, garantindo verificação estrita de conformidade com o schema Prisma sem degradar a inferência concreta dos campos hierárquicos (`scope.environment.project.organizationId`) necessária aos testes de unidade.

Resultado: `npm run typecheck` executado com **código de saída 0**.

## 4. Auditoria dos 12 Requisitos Cross-Tenant e RBAC

A suíte `web/tests/saas-tenant-isolation.test.ts` foi expandida de 4 para 9 testes automatizados cobrindo exaustivamente:

1. **Tenant A não lê OperationalAssessment do Tenant B**: `operationalAssessmentScopeWhere` exige estritamente `project.organizationId === context.organization.id`.
2. **Tenant A não executa Assessment do Tenant B**: O lookup na rota de runs utiliza o escopo autenticado do tenant. Identificadores de outros tenants resultam em `null` / 404 (`mutationNotFound()`).
3. **Project deve pertencer à Organization correta**: Validado no predicado `where.environment.project.organizationId`.
4. **Environment deve pertencer ao Project correto**: Validado no predicado `where.environment.project.id`.
5. **Assessment deve pertencer ao Environment correto**: Validado no predicado `where.environment.id`.
6. **VIEWER não executa analysis**: `hasTenantPermission(MembershipRole.VIEWER, "analysis:execute") === false`.
7. **REVIEWER não executa analysis**: `hasTenantPermission(MembershipRole.REVIEWER, "analysis:execute") === false`.
8. **OPERATOR executa analysis, mas não gerencia memberships**: `hasTenantPermission(MembershipRole.OPERATOR, "analysis:execute") === true` e `hasTenantPermission(MembershipRole.OPERATOR, "membership:manage") === false`.
9. **Organização suspensa não pode executar análise**: O escopo filtra `organization: { status: "ACTIVE" }` e o resolver de sessão rejeita organizações com status `SUSPENDED` ou `ARCHIVED`.
10. **Run nunca sobrescreve Run anterior**: Relação 1:N entre Assessment e Runs. Cada run possui ID único, data de início imutável e hash de recibo criptográfico SHA-256 (`auditReceiptHash`).
11. **EvidenceSnapshot permanece vinculado ao tenant correto**: O snapshot referencia `environmentId` e calcula hash canônico JCS SHA-256.
12. **Demo pública não persiste em nenhum tenant**: A rota `/api/analyze-environment` opera em modo `PUBLIC_STATELESS_DEMO` com `persisted: false` e `tenantBound: false`.
