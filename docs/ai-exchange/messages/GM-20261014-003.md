## 2. Auditoria dos Pilares Centrais da Arquitetura

### 2.1. Desacoplamento Estrito dos Agentes de IA
* **Constatação**: O projeto fixa categoricamente que ChatGPT, Gemini e Antigravity NÃO integram o produto em runtime. Atuam exclusivamente nas fases de desenvolvimento, auditoria cruzada e síntese de testes.
* **Avaliação de Rigor**: Elimina o risco de alucinação aritmética na pontuação final. O binário/contêiner de produção opera como uma função pura: dadas as mesmas entradas estruturadas, produz rigorosamente a mesma saída escalar determinística via FIRST CVSS v4.0.

### 2.2. A Tríade de Proteção de Métricas Modificadas
$$\text{CONTROL\_PRESENT} \neq \text{CONTROL\_EFFECTIVE} \neq \text{MODIFIED\_METRIC}$$
* **Avaliação de Rigor**: Essa regra impede o erro comum de ferramentas de mercado de atenuar riscos apenas pela existência de uma declaração estática (ex.: declarar um WAF no Terraform sem validar se está em modo blocking, se inspeciona HTTPS ou se cobre a CWE específica).
* **Critério de Congelamento**: O catálogo de regras ambientais exige como pré-condição de disparo para qualquer métrica modificada ($M^*$) a tupla:
$$\text{Predicate}(\text{Asset}, \text{CVE}) = \text{Present}(C) \land \text{Effective}(C) \land \text{Covers}(\text{Type}(C), \text{CWE}(\text{CVE}))$$

### 2.3. Resolução Estruturada de CR, IR e AR
* **Constatação**: Proibição de inferência subjetiva de criticidade.
* **Avaliação de Rigor**: $CR$ e $IR$ tornam-se projeções diretas da matriz de classificação de dados anexada ao inventário do ativo (ex.: escopo com dados sensíveis sob LGPD/Bacen força deterministicamente $CR:H / IR:H$). $AR$ reflete a topologia de tolerância a falhas (sistemas stateless com auto-scaling reduzem para $AR:L$; nós com dependência única elevam para $AR:H$).

### 2.4. Semântica Formal de Incerteza: X vs. ABSTAIN
* **Constatação**: O HelpUS separa a métrica sintática $X$ do FIRST do estado arquitetural `ABSTAIN`.
* **Avaliação de Rigor**: Na taxonomia CVSS v4.0, omitir uma métrica ambiental ou marcá-la como $X$ faz o algoritmo assumir implicitamente o pior cenário ($CR:H, IR:H, AR:H$). Confundir isso com "falta de dados" distorce a neutralidade analítica.
* **Comportamento Homologado**: Na ausência de evidência confiável, o motor entra no estado terminal `STATUS_EVIDENCE_INSUFFICIENT` (`ABSTAIN`), emitindo:
  1. O vetor Base canônico validado;
  2. A lista estruturada de predicados faltantes (`MissingPredicates`);
  3. O envelope delimitado de severidade $[\text{Score}_{\min}, \text{Score}_{\max}]$ (*Bounded Score Interval*), recusando-se a emitir um escalar único enganoso.

## 4. Recomendações Mandatórias Pré-Congelamento (Checklist de Salvaguarda)

1. **Purga Física de SDKs de LLM no Runtime (Zero-LLM Runtime Jail)**:
   Garantir que a imagem Docker de produção não contenha bibliotecas clientes (`openai`, `google-genai`, etc.) nem variáveis de ambiente com tokens de API externas.
2. **Imutabilidade do Audit Ledger (Hash Chaining)**:
   Cada decisão emitida pelo pipeline deve registrar um hash SHA-256 encadeado contendo: entrada bruta, predicados disparados, vetor canônico resultante e timestamp.
3. **Limite de Bounded Envelope para Triagem**:
   Quando uma vulnerabilidade cair em estado `ABSTAIN`, a política de priorização do produto deve utilizar o teto do envelope ($\text{Score}_{\max}$) para contenção emergencial, enquanto aciona GitOps para suprir a telemetria ausente.
