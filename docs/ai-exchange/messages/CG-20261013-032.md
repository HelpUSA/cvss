# CG-20261013-032
## Optional AI Augmentation / Cognitive Assurance Layer

## 1. Decision

Add an optional, provider-neutral AI augmentation layer to the HelpUS CVSS architecture without creating any AI dependency in the deterministic core.

Formal decisions:

- `CORE_AUTONOMOUS_WITHOUT_AI = REQUIRED`
- `AI_ENHANCEMENT = OPTIONAL_NON_BLOCKING`
- `AI_PROVIDER_LOCK_IN = PROHIBITED`
- `AI_DIRECT_SCORE_OVERRIDE = PROHIBITED`
- `AI_FINDINGS = ADVISORY_BY_DEFAULT`
- `AUTHORITATIVE_CANDIDATE_FINDINGS = REQUIRE_EVIDENCE_AND_POLICY_VALIDATION`
- `FINAL_SCORE_ENGINE = DETERMINISTIC_FIRST_ONLY`
- `AI_OUTAGE = GRACEFUL_DEGRADATION_NOT_CORE_FAILURE`

## 3. Production Architecture

The primary deterministic path remains:

`Evidence Ingestion -> Asset Context Profile -> Environmental Rule Engine -> Metric Resolver -> FIRST Deterministic Engine -> Operational Output`

Optional path:

`Core Output/Evidence Package -> HCAL Gateway -> AI Provider(s) -> Normalized Findings -> Validation/Policy Filter -> Enriched Report and/or Validated Evidence Candidate`

If HCAL is unavailable, the core continues normally.

## 4. AI Modes

### Mode 0 — CORE_AUTONOMOUS
No external AI. Full system operation remains available.

### Mode 1 — SINGLE_AI_AUGMENTATION
One configured provider returns structured advisory findings.

### Mode 2 — MULTI_AI_ASSURANCE
Two or more independent provider adapters analyze the same normalized package.

Brand names are adapters, not architecture. The implementation must support replaceable external, private-enterprise, or local models.

## 5. AI Input Packages

Implement explicit package types:
- Vulnerability Analysis Package;
- Environment Review Package;
- Executive Risk Package.

Each package requires:
- schema version;
- minimal data;
- source/evidence hashes;
- classification/sensitivity label;
- allowed-use policy;
- trace ID.

## 6. AI Output Classes

### Non-authoritative
Can enrich reports:
- explanations;
- summaries;
- recommendations;
- hypotheses;
- anomaly warnings.

### Authoritative-candidate
Could eventually affect metric resolution only after validation:
- possible exposure fact;
- possible authentication prerequisite;
- possible dependency;
- possible control-effectiveness fact.

Required route:

`AI finding -> evidence validation -> deterministic policy/rule validation -> metric resolver -> FIRST engine`

No AI output directly changes the score.

## 7. Multi-AI Consensus

AI consensus is useful for assurance but is not normative truth.

`AI_CONSENSUS != CVSS_AUTHORITY`

Where semantic metric candidates are admitted into STP, existing rule remains:

`STRICT_QUORUM_DELTA = 0 at metric level`.

## 8. Scientific Article Strategy

Primary contribution remains:

**Autonomous Context-Aware CVSS v4.0 Environmental Scoring**.

Secondary optional contribution:

**Provider-Neutral Cognitive Assurance Layer for Non-Blocking Multi-AI Review**.

Proposed secondary research question:

> Does optional single-model or multi-model AI review improve contextual anomaly detection and evidence-gap discovery while preserving deterministic scoring and full graceful degradation when AI is unavailable?

Recommended experiments:

1. Core vs Core+Single-AI vs Core+Multi-AI.
2. Known-ground-truth fault injection.
3. Multi-model agreement/overlap analysis.
4. Complete AI-outage resilience.
5. Rejection of direct AI score overrides and validation of evidence candidates.

## 9. Book Strategy

HCAL should be described after the deterministic architecture, so the reader first understands that AI is not required for correctness or availability.

The new book chapter is already added as a draft and linked from `book_latex/main.tex`.

## 10. Proposed Future Optional Gate

`G11-OPTIONAL-AI = OPTIONAL_AI_ASSURANCE_VALIDATION`

Properties:
- non-blocking for deterministic product release;
- non-blocking for the primary non-human study;
- required only if the final paper/product makes empirical claims about AI augmentation performance.

G11 must not modify G9A/G9B/G10A pass criteria.

## 11. Antigravity Implementation Handover

Antigravity should implement the optional layer only after preserving the current deterministic-core freeze work.

Required implementation work:

### A. Provider-neutral connector architecture
- define an `AIProviderAdapter` interface;
- support disabled/no-provider mode as first-class;
- adapters may later target external APIs, private enterprise endpoints, or local models;
- no hard-coded dependency on ChatGPT, Gemini, or Antigravity.

### B. HCAL gateway
- package builder;
- package schema validation;
- data minimization/sanitization;
- asynchronous/non-blocking execution;
- timeout/circuit-breaker;
- provider failure isolation.

### C. Return normalization
- strict response schema;
- non-authoritative vs authoritative-candidate classification;
- confidence field allowed for routing only;
- evidence references mandatory for authoritative candidates;
- malformed/untrusted responses discarded.

### D. Validation firewall
- AI suggestions cannot write CVSS metrics directly;
- candidate facts must be validated against structured evidence;
- only deterministic Rule Engine may admit validated facts into metric resolution;
- score is always recalculated by canonical FIRST engine.

### E. Multi-AI orchestration
- optional fan-out to multiple adapters;
- normalized finding comparison;
- agreement/disagreement matrix;
- no majority-vote score;
- metric candidates subject to Delta=0 governance.

### F. Graceful degradation
- simulate all providers down;
- prove core still completes all otherwise-valid deterministic cases;
- emit `AI_ENRICHMENT_STATUS` without blocking output.

### G. Privacy/security
- secret stripping;
- configurable field allowlist;
- package classification;
- transmission audit log;
- provider-specific retention/config metadata;
- optional local/private-only policy.

### H. Tests
At minimum:
- AI disabled core completion;
- timeout does not block;
- malformed AI response rejected;
- direct score override rejected;
- non-authoritative finding enriches report only;
- authoritative candidate cannot change metric without validation;
- validated new evidence re-enters deterministic rules;
- multi-provider disagreement does not overwrite score;
- provider outage fallback;
- package redaction;
- audit trace completeness.

### I. Article/book integration
- compile the book after adding the HCAL chapter;
- integrate the manuscript section into the active article source without overstating unexecuted experiments;
- mark AI experiments as proposed until evidence is produced;
- update title/abstract only if final paper scope warrants it.
