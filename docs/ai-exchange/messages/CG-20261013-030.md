## 3. Critical Gap A — Runtime Still Forces Human Review

The current production-path implementation in `core/ai_evidence_engine.py` and `core/cvss_environmental_engine.py` still behaves as legacy HITL-first logic:

- `_abstain()` returns `HUMAN_REVIEW_REQUIRED`;
- successful inference returns `human_review_status = required`;
- successful inference returns `auto_downgrade_permitted = False`;
- `cvss_environmental_engine.calculate()` preserves those human-review-required semantics.

Therefore the actual runtime is **not yet autonomous-by-default STP**.

Required remediation:
- create explicit `AUTO_ACCEPT`, `AUTO_ACCEPT_WITH_WARNING`, `HUMAN_REVIEW_REQUIRED`, and `ABSTAIN` states;
- deterministic high-quality structured-evidence path must be capable of `AUTO_ACCEPT`;
- semantic path must be capable of `AUTO_ACCEPT` only when strict Delta=0 metric quorum and all policy checks pass;
- human review remains exception-only;
- score math stays deterministic.

## 5. Critical Gap C — STP Quorum Rule Is Incorrect in Architecture Document

`AUTONOMOUS_ENVIRONMENTAL_CONTEXT_ARCHITECTURE.md` currently states HITL trigger:

`Delta >= 1 divergence in semantic advisory parsing`

This conflicts with the authorized governance rule:

**STRICT_QUORUM_DELTA = 0 at metric level**.

Any required metric disagreement must break STP eligibility, even if final-score delta is small or zero.

Required remediation:
- replace Delta>=1 logic;
- implement exact metric-level agreement for semantic STP;
- final-score agreement alone is insufficient.

## 6. Critical Gap D — 3%–5% Sampling Is Mischaracterized

The architecture states that post-hoc random sampling of 3%–5% is used “to comply with NIST AI RMF, ISO/IEC 27001, and ISO/IEC 42001”.

This wording is too strong.

The 3%–5% rate is an internal HelpUS governance choice, not a percentage mandated by those standards/frameworks.

Required remediation:
- state that the sample supports monitoring, measurement, review, drift detection, and continual improvement;
- explicitly label the rate as `HELPUS_INTERNAL_CONTROL`;
- do not imply standards prescribe 3%–5%.

## 7. Critical Gap E — Unsupported 90%–95% Routine-Automation Claim

The architecture document states:

`Routine Flow (90% to 95% of volume)`

No current evidence establishes that 90%–95% of real workloads will qualify for STP.

Required remediation:
- remove the fixed percentage or label it as a future operational target/hypothesis;
- actual STP coverage must be measured empirically after deployment/simulation.

## 8. Critical Gap F — Rule Catalog Contains Ambiguous / Overbroad Rules

### MAV-003

Consequence is `MAV = L or P`, which is not deterministic.

Required remediation:
- split into distinct rules for LOCAL_ONLY and PHYSICAL_ONLY;
- one rule must produce one unambiguous output.

### MPR-001

Current rule maps mandatory enterprise SSO/MFA gateway from Base PR:N to MPR:L/H.

This may be semantically invalid if the gateway control does not represent privileges required on the vulnerable system before exploitation.

Required remediation:
- re-check against FIRST metric semantics;
- do not reinterpret authentication perimeter controls as MPR unless the rule proves the actual exploit prerequisite matches the metric definition;
- otherwise preserve X/base and record the control separately.

### MSC-001

Current rule sets `MSC=N, MSI=N, MSA=N` solely from zero lateral egress and no cross-zone trust.

This is too broad because subsequent-system impact can exist without generic lateral network egress, depending on vulnerability semantics, trust relationships, shared resources, identity/control-plane effects, or same-enclave dependencies.

Required remediation:
- split confidentiality/integrity/availability rules;
- require vulnerability-specific evidence that the subsequent impact path is actually eliminated;
- fail closed when uncertain.

### MAC-002

The rule is conceptually plausible but needs explicit FIRST-semantic evidence and regression fixtures proving target-specific exploit engineering, not generic hardening presence.
