# CG-20261014-040
## Operational SaaS Multi-Tenant and SuperAdmin Foundation

## 1. Scope

This round improves the operational website around the frozen deterministic
CVSS engine. It does not change CVSS scoring math, the frozen rule catalog, or
C1/C2.

The target product hierarchy is:

`User -> Organization -> Project -> Environment -> Assessment -> Run -> Evidence Snapshot -> Review/Audit`

## 2. Implemented in Git by ChatGPT

### Google-only operational identity

The existing Better Auth Google provider remains the production login path.

Added:

`web/src/lib/platform-superadmin.ts`

The canonical platform SuperAdmin is configured by:

`PLATFORM_SUPERADMIN_EMAIL`

with the approved production value:

`helpus.ecommerce@gmail.com`

The Better Auth user-create hook now assigns `PLATFORM_ADMIN` automatically
when the Google identity email matches the canonical configured SuperAdmin.

A production reconciliation script was added:

`web/scripts/reconcile-google-platform-superadmin.ts`

Command:

`npm run auth:reconcile-google-superadmin`

The script refuses promotion unless the existing account is linked to provider
`google`.

### Global user management

Added:

- `web/src/lib/platform-user-administration.ts`
- `GET /api/platform/users`
- `PATCH /api/platform/users/{userId}`
- `/app/admin/users`

Implemented controls:

- list users and linked providers;
- inspect status/platform role/membership count/session count;
- ACTIVE / SUSPENDED / DISABLED lifecycle;
- automatic revocation of every active session after suspension/disablement;
- global platform-role changes only by the canonical SuperAdmin;
- canonical SuperAdmin cannot be suspended, disabled or demoted;
- all mutations append `SecurityAuditEvent`;
- no implicit tenant access is granted by PLATFORM_ADMIN.

A “Gerenciar usuários” entry point was added to the operational home for
platform administrators.

## 3. Important current finding

The repository already contains a serious multi-tenant foundation:

- Google OAuth / Better Auth;
- server-side sessions;
- organizations;
- memberships;
- ADMIN / OPERATOR / VIEWER / reserved REVIEWER;
- projects;
- environments;
- invitations;
- session controls;
- security audit events.

However, the current public `POST /api/analyze-environment` is still not
tenant-authenticated and accepts an ephemeral analysis request directly.

It must remain a demo/compatibility path, not the final operational production
path.

## 4. Required Antigravity continuation

The following work requires local/deployment access or is large enough to be a
dedicated implementation round.

### A. Production Google OAuth / database reconciliation

Configure only in secret/environment management, never Git:

- `GOOGLE_CLIENT_ID`
- `GOOGLE_CLIENT_SECRET`
- `BETTER_AUTH_SECRET`
- `BETTER_AUTH_URL`
- `AUTH_TRUSTED_ORIGINS`
- `DATABASE_URL`
- `PLATFORM_SUPERADMIN_EMAIL=helpus.ecommerce@gmail.com`

Then:

1. back up the production database;
2. sign in once with the canonical Google account if the user does not exist;
3. verify the Better Auth Account provider is `google`;
4. run `npm run auth:reconcile-google-superadmin`;
5. verify `PLATFORM_ADMIN / ACTIVE`;
6. verify audit event;
7. verify normal Google accounts remain `USER`.

Do not create a password credential for the canonical SuperAdmin.

### B. Persistent operational assessment schema

Implement additive tenant-scoped models for operational procedures/runs.
Because the repository already has legacy research models named `Run` and
`Assessment`, do not silently repurpose them.

Recommended new names:

- `OperationalAssessment`
- `OperationalAssessmentRun`
- `EvidenceSnapshot`
- `AssessmentReview`
- `OrganizationPolicyVersion`
- `PlatformSetting`

Every object must be reachable through Environment -> Project -> Organization.

### C. Authenticated tenant analysis route

Refactor the deterministic calculation out of the public HTTP route into a
shared service, then add tenant-scoped execution:

`POST /api/organizations/{org}/projects/{project}/environments/{env}/assessments/{assessmentId}/runs`

Requirements:

- session required;
- ACTIVE user;
- ACTIVE membership;
- `analysis:execute`;
- project/environment ownership validation;
- evidence snapshot before execution;
- persisted run;
- engine/rule/policy hashes;
- audit receipt;
- no client-supplied tenant ID/role trusted for authorization.

Keep the public route only as rate-limited stateless demo compatibility, or
disable it for production if product policy chooses authenticated-only use.

### D. REVIEWER workflow

Activate the existing REVIEWER role with `decision:review` only after the
review model/queue is present.

Implement approve/reject/request-evidence transitions and keep organizational
approval separate from deterministic scoring.

### E. SuperAdmin organization and platform management

Add global SuperAdmin management for:

- organization list/search;
- organization ACTIVE/SUSPENDED/ARCHIVED lifecycle;
- tenant-admin recovery/assignment;
- platform feature flags;
- per-tenant quotas/rate limits;
- retention/export policy;
- maintenance mode;
- integration/service-account enablement;
- platform audit review.

Store non-secret platform settings in a versioned audited table. Secrets stay
in the deployment secret manager.

### F. Required E2E / integration tests

Add and return evidence for:

1. canonical Google SuperAdmin login;
2. ordinary Google user remains USER;
3. canonical SuperAdmin cannot be disabled/demoted;
4. suspended/disabled user loses all sessions;
5. non-canonical platform admin cannot change platform roles;
6. cross-tenant reads/mutations denied;
7. tenant analysis cannot select another tenant's project/environment;
8. suspended organization cannot execute analyses;
9. public demo cannot persist into a tenant;
10. operational run history is immutable/versioned rather than overwritten.
