## 3. Blocking Finding A — G9A Hash Does Not Fully Bind Executable Rule Semantics

`compute_catalog_hash()` currently hashes rule metadata plus `rule.evaluator.__code__.co_code`.

This is insufficient to guarantee sensitivity to every executable logic change.

Python `co_code` contains bytecode instructions, but constants and other code-object semantics are stored separately (for example `co_consts`, names, defaults, nested code objects). A change such as replacing one literal comparison/value with another can preserve the same bytecode instruction sequence while changing the actual evaluator behavior.

Therefore the claim that the catalog hash guarantees detection of any operational rule change is not yet justified.

The current test `test_executable_catalog_is_single_source_of_truth` only checks that evaluators are callable, a sample rule executes, and the current hash has length 64; it does not mutate executable semantics and prove hash sensitivity.

### Required correction

Use one of these robust bindings:
- hash the exact source bytes of the canonical executable module plus catalog version; or
- serialize the complete relevant code object recursively, including `co_code`, `co_consts`, names, defaults/closures where applicable; or
- bind both module-file SHA-256 and a canonical rule-structure hash.

Then add a regression test that changes evaluator semantics in a controlled fixture and proves the binding changes.

Until corrected:
`G9A = FINAL_HASH_BINDING_CORRECTION_REQUIRED`.

## 5. Blocking Finding C — HCAL Timeout Is Not Truly Non-Blocking for a Hung Provider

`HCALGateway.execute_review()` uses:

`with ThreadPoolExecutor(...) as executor:`

and catches `as_completed(..., timeout=...)` timeout events.

However, exiting the `with` block calls executor shutdown with the default wait behavior. A provider thread that actually hangs beyond the timeout can therefore keep the caller blocked until that thread returns.

The current mock timeout does not simulate a hung call; it immediately returns a `TIMEOUT` response. Thus the 10/10 suite does not prove the stated non-blocking guarantee against a genuinely stuck provider.

### Required correction

Implement a hard isolation/cancellation design appropriate to provider calls, for example:
- provider-native network timeouts plus bounded executor lifecycle;
- executor shutdown with `wait=False`/cancel strategy where safe;
- process isolation for untrusted/hard-hanging adapters;
- or async I/O with enforceable cancellation semantics.

Add a test where a mock provider really sleeps/hangs longer than the gateway timeout and assert wall-clock return stays within the defined bound.

Until corrected:
`G11-OPTIONAL-AI = PROTOTYPE_IMPLEMENTED_HARDENING_REQUIRED`.

This does not block the deterministic core release by itself because G11 is optional.
