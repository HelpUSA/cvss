One important authorization gap remains.

## Blocker — suspended/disabled PLATFORM_ADMIN is not revalidated by the review route

The Prisma `User` model has:
- `status` = ACTIVE / SUSPENDED / DISABLED;
- `platformRole`.

The review route queries only:

`select: { platformRole: true }`

It does not verify `status === ACTIVE`.

`auth.ts` checks status when a session is first created, but a previously issued session can remain present if the user is later suspended or disabled.

The repository already has `getActiveSession()` in `web/src/lib/session.ts`, which revalidates authoritative user status on each use and revokes sessions when the user is not active, but `/api/review/decision` does not use that helper.

Therefore a user who obtained a session while ACTIVE and is subsequently changed to SUSPENDED/DISABLED can still pass the review route if their persisted platform role remains `PLATFORM_ADMIN`.

### Required correction

For every privileged HITL mutation:
- authoritative lookup must select `status` and `platformRole`;
- missing user -> deny;
- SUSPENDED/DISABLED -> deny and preferably revoke sessions;
- only ACTIVE + PLATFORM_ADMIN -> allow.

Add explicit tests for:
- suspended platform admin;
- disabled platform admin;
- missing authoritative user.

### G4 decision

**G4 = FAIL / PARTIAL**

The fail-closed DB/persistence work is real, but privileged active-user authorization is not complete.
