# CG-20261014-041
## SaaS Operational Assessment Execution Foundation

Implemented in Git without touching the frozen deterministic baseline or C1/C2.

## Implemented

### Prisma operational lifecycle

Added enums/models for:

- OperationalAssessment
- OperationalAssessmentRun
- EvidenceSnapshot
- AssessmentReview
- OrganizationPolicyVersion
- PlatformSetting

All operational assessment data is tenant-reachable through
Environment -> Project -> Organization and includes indexes for tenant-scoped
lookup.

No existing legacy research Run/Assessment model was renamed or repurposed.

### Shared analysis service

Created:

`web/src/lib/environmental-analysis-service.ts`

The previous environmental calculation logic was extracted from the HTTP route
into a shared deterministic TypeScript service with typed inputs/results and
audit receipt generation.

### Public demo route

`POST /api/analyze-environment` now:

- calls the shared service;
- is explicitly tagged `PUBLIC_STATELESS_DEMO`;
- never persists into a tenant;
- returns `persisted=false`;
- applies a best-effort in-process fixed-window rate limit;
- returns HTTP 429 on local limit exhaustion.

NOTE: this rate limiter is intentionally a lightweight application safeguard.
For multi-instance/serverless production, Antigravity should add a distributed
edge/provider rate-limit control.

### Tenant-scoped operational run route

Created:

`POST /api/organizations/[organizationSlug]/projects/[projectId]/environments/[environmentId]/assessments/[assessmentId]/runs`

Security flow:

1. same-origin JSON mutation validation;
2. active session;
3. authoritative organization membership resolution;
4. required `analysis:execute`;
5. Project -> Organization validation;
6. Environment -> Project validation;
7. OperationalAssessment -> Environment validation;
8. evidence JCS hash and EvidenceSnapshot persistence;
9. shared deterministic analysis execution;
10. OperationalAssessmentRun persistence;
11. SecurityAuditEvent persistence.

No organization role/ID supplied by the browser is trusted for authorization.

### Reviewer RBAC

Activated the existing REVIEWER role for:

- organization:read
- project:read
- environment:read
- decision:review

REVIEWER does not receive analysis:execute or membership:manage.

### Tests

Created:

`web/tests/saas-tenant-isolation.test.ts`

and npm command:

`npm run test:saas:unit`

The tests cover the tenant hierarchy scope construction and reviewer/viewer
permission boundaries.
