## G4 — Web / Auth / HITL

Several important fixes are real:

- `BETTER_AUTH_SECRET` now fails closed;
- email/password auth is disabled;
- Google login uses `authClient.signIn.social(...)`;
- no client-created auth session cookie remains in the new login component;
- server endpoint `/api/review/decision` returns 401 for unauthenticated requests and attempts a role check.

However, the current HITL endpoint has critical correctness problems.

### Blocker A — authorization role is impossible under the current Prisma schema

The endpoint allows only:

`userRole === "SUPERADMIN"`

But the actual Prisma enum is:

`PlatformRole { USER, PLATFORM_ADMIN }`

There is no `SUPERADMIN` value in `web/prisma/schema.prisma`.

The existing bootstrap code creates:

`platformRole = "PLATFORM_ADMIN"`

Therefore a real authoritative database user with the highest current platform role will be rejected by the review route.

The 8/8 test suite does not detect this because it mocks a session containing an impossible schema value:

`platformRole: "SUPERADMIN"`.

This is a test-fixture false positive relative to the actual persistence model.

### Blocker B — no persistent approval/rejection mutation

The endpoint creates a receipt and returns HTTP 200, but it does not persist an approval/rejection transition in Prisma.

No review-decision model or `SecurityAuditEvent.create(...)` mutation is executed in this route.

Therefore it is not yet a durable HITL decision mutation; it is an authenticated receipt-generation endpoint.

### Blocker C — policy provenance is silently fabricated when missing

The endpoint defaults missing values to:

- `organizationPolicyId = "helpus-operational-pci-segmented"`
- `policyVersion = "1.0.0"`
- `rulesetVersion = "1.0.0"`
- `calculatorVersion = "0.2.0-aligned-first-cvss40"`

This conflicts with the project's fail-safe policy requirement.

For an approval receipt, policy/ruleset/calculator binding must be explicit or resolved authoritatively server-side from stored assessment state. It must not be silently invented inside the approval endpoint.

### Blocker D — tests mock authorization instead of integrating with real role persistence

The current security tests replace:

`auth.api.getSession`

with a mock.

Unit tests are useful, but they do not prove BetterAuth + Prisma + actual platform-role enforcement.

### G4 decision

**G4 = FAIL**

Required:
- reconcile role model and route check, preferably using the existing authoritative `PLATFORM_ADMIN` model or a deliberately migrated role enum;
- fetch authoritative active user/role server-side;
- persist APPROVED/REJECTED decision + rationale + assessment ID + reviewer + timestamp + policy/ruleset/calculator provenance;
- require explicit/resolved policy binding, no defaults;
- add integration tests against the real role schema and persistence layer.
